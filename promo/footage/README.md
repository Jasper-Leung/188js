## 怎么加长

改一个数字就行：

```bash
node tools/scenery.mjs 40          # 每条 40 秒 -> 2400 帧
node tools/scenery.mjs 120         # 每条 2 分钟
node tools/scenery.mjs 14 tea      # 只重录名字里含 tea 的那一条
```

慢放版（更适合配旁白）：

```js
// tools/scenery.mjs 里把截图前加一行
await page.evaluate(() => { window.gift188.cine.speed = 0.5; });
```

## 这批素材为什么不会有顿挫

`?cine=1` 把主循环切成**确定性模式**：每个 rAF 固定推进 `fixedDt`（1/60 秒），
不看墙上时钟。于是**第 N 张截图一定对应第 N/60 秒的游戏时间**，
帧与帧之间的运动量恒定。机器慢只会让整段变慢放，不会产生停顿。

> `mpdecimate` 在这批里会报 36~61 帧"近似重复"（841 帧中占 5~7%）。
> **那不是顿挫**——推轨镜头 14 秒只走 70 米，每帧位移约 0.1 米，
> 远景上像素变化本来就小。之前那条快速移动的测试里是 241 进 240 出。
> 两种情况都**没有**真正的重复帧堆积。

## 加新镜头

`tools/scenery.mjs` 里的 `SHOTS` 数组，每条是一个沿环线的推轨：

```js
{ name: '07-my-shot', from: 430, to: 500, y: 2.9, look: 80 }
//            名字            起始弧长  结束弧长  机位高 看向点前伸(米)
```

弧长是沿 1228.8 m 环线的米数。`from`/`to` 决定机位怎么走，
`look` 是看向点永远在前方多远。

### 机位高度的硬约束

**机位必须留在路面上，高度 2.6~3.2 m。**

行道树离路 >= 16 m、高 8~12 m；竹子能到 22 m。试过把相机抬到 32 m 想拍全景，
结果直接插进树冠/竹丛里（`shots/scout/` 的接触印相里那几张 `air-*` 就是这么废掉的）。
空中机位要做的话得先解决遮挡，不是调个 y 就行。

### 先勘察再录

`tools/scout.mjs` 每个候选机位只拍**一张**，`tools/sheet.mjs` 拼成接触印相：

```bash
node tools/scout.mjs && node tools/sheet.mjs
```

看着印相挑位置，再去录。录满 6 条再发现机位被树挡着，浪费的是几分钟；
看印相只要十几秒。

## 录 walkthrough 踩过的坑（都是"不报错"的那种）

这七条每一个都让**一整轮录制变成废片**，而且代码里一句错都不报。

### 1. `--mute-audio` 会让 `audio.unlock()` 永不返回

`startRide()` 第一句就是 `await audio.unlock()`。加上静音参数后这一步不返回，
`phase` 卡在 `'title'`，车一动不动，而脚本照样往下印 "prologue done"。
正解是 `--autoplay-policy=no-user-gesture-required` 且**不加** `--mute-audio`。

### 2. `window.gift188` 在 cine 模式下曾经是"开机快照"

`installCineMode` 把上一个 getter 的**返回值**存了下来，于是
`bike.x / bike.z / speed / heading / phase` 全是启动那一刻的值。

症状：车**真的在动**，而录制脚本读到的是"车没动"，弧长永远停在出生点。
每一项单独看都合理（`canRide` 恒为 true、离路距离恒为 0），
合起来才是 bug。已修：存 getter 本身，每次读都重新调用。

### 3. 车是**倒着**停的

`world` 在驿站 0 旁用 `ride.spawn(near.x, near.z, 0)` 起手，
heading=0 意味着车头朝 -Z，而这条路的走向在这里是 **+Z** —— 要转 159° 才顺路。

控制器为了掉头会一直满舵，而满舵半径小于前视距离，**根本转不过来**：
实测 `travelled 0m`、弧长钉在 37m、车在半径约 19m 的圆上打转。
正解：`cine.goto(x, z, heading)`，航向按**道路走向**算
（`h = atan2(-dx, -dz)`），直接摆正再出发。

### 4. "限制在上一步弧长附近找点"是**黏的**

想在自交口避免跳支，于是把搜索范围限制到 `prevArc` 附近。
结果车开出去几米后，**起点那批采样点仍在 20m 内、且弧长更接近 `prevArc`**，
于是永远赢——弧长钉住不动，里程永远是 0，车只会绕着起点打转。

正解是**沿切线做航位推算**：每帧只挪 `位移 · 切向`（约 0.1m），
单调、不可能跳支；再每隔 60 帧用最近点缓慢校正漂移，
且**只在两者足够接近时**校正（接近 = 不在自交口上）。

### 5. 航向约定错 90° 不报错

`ride.ts` 的 `_fwd = (-sin h, -cos h)`，所以由前向反解航向是 `h = atan2(-dx, -dz)`；
而 `heading += -steer * k`，所以 **err>0 按 a、err<0 按 d**。
写反了只会表现为"车往回骑"。这两个符号由 `npm run promo:wt-probe` **实测**钉住。

### 6. 驿站够不着：沿中心线骑永远打不了卡

驿站横向偏出路面约 18m，而 `interactAt` 的判定是 `distance <= reach`。
沿中心线骑过去最近也只到 ~18m —— 真玩家会往路肩上偏一点，脚本也得会：
进站 40m 内改瞄**驿站本身**，而不是继续瞄前方的中心线点。

### 7. 一圈跑完，弧长会绕回 0

用累计里程判断"跑完没"，不能用当前弧长——满圈后 `arc` 回到起点，
只看 `here.arc` 永远到不了终点。
