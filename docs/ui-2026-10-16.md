# 2026-10-16 UI、小游戏美术与剧情交互验收

本轮接续本地 v1.0.2 代码，范围为 19:42 提出的五类优化。没有更改章节目标、小游戏胜负规则、奖励或存档结构；不包含重新发版。原有 release.zip、v1.0.2 标签和交付包保留。

## 审计结论与实施顺序

- 工程是 TypeScript strict + three.js + Vite；小游戏使用 Canvas 2D。Tauri 桌面壳读取同一份 dist。没有独立手机原生客户端；继续按手机网页与 Windows/macOS/Linux 桌面客户端适配。
- 原有 clean 模式隐藏整个 UI 根节点，也会关闭摇杆命中；道具栏四格常驻；经营按钮嵌在任务栏里。先分离显示偏好和移动输入，再调整布局。
- 原剧情跳过按钮只有键盘绑定，鼠标点击冒泡成普通 advance。实际剧情由 WorldEvent 的选定文本分支和打卡完成回调组成，不是任意图结构。跳过需复用宿主的过场收尾，并防止重复回调。
- 小游戏背景由 chrome.ts 绘制。原 hex() 按带 # 的字符串解码，但主题表传入六位裸色值，造成颜色解析错误。先修色值，再重新绘制各场景。
- 原路灯地面光斑是纯色圆形网格，存在几何硬边。改为共享径向透明纹理与实例化平面。
- 风险集中在触控重复激活、模态界面遮挡、剧情锁未释放、背景绘制成本。通过指针归属、幂等收尾、唯一回归入口与真实浏览器交互验证。

人工补验清单（每种目标设备分别执行）：

1. `npm run dev` 或 HTTPS 部署打开游戏；桌面可 `npm run build && npm run preview`。有对应工具链时 `npm run desktop:dev` 或安装平台包。分别使用现有存档与新局。
2. 开局在长段落未计时结束时点“继续/关闭”；连续推进、跳末张、关闭末张。确认不跳两张、不重复出现，能继续骑行、进小游戏。
3. 右上角隐藏全部界面；在原摇杆区域按住并拖动，确认摇杆不可见但车辆移动，松手后停止输入。点击原隐藏位置恢复；键盘 H 恢复。将某项键位设为 H 后确认原动作仍有效，Shift+H 可恢复界面。
4. 分别开关四类模块，刷新确认偏好；道具默认仅一颗按钮，展开后点选已拥有材料，再收起。确认任务隐藏不误藏经营入口，功能隐藏不影响移动。
5. 左手持续操纵摇杆，右手依次点换车、伸手、打卡、道具、静音、暂停；取消触摸、切后台后无持续加速/长按。切换左右手配置再做一遍。逐个打开经营、商店、设置、琴音林两个入口，确认滚动、退出和按钮热区。
6. 横屏覆盖 16:9、19.5:9、20:9；竖屏提示后继续或旋转；检查刘海与底部手势区。桌面缩放 100%/125%/200%，手机调整系统文字大小；确认长文按钮、菜单和小游戏的触摸坐标仍对齐。
7. 各玩一局云/茶/琴/竹/禽，以及自由演奏；观察背景、前景可读性、取消/成功/失败出口与多指。琴弦按原规则工作，背景不过亮；竹庭长标题不裁切。
8. 普通多段剧情点末尾，只显示末句；首访驿站点末尾直接进小游戏；在集齐碎片后回家点末尾进入合成。反派剧情不能串入未选分支；离开后再访检查过场与相机恢复。
9. 设置固定 06:00、12:00、18:00、22:00，观察路灯开关与地面光晕；沿坡地骑过，确认没有明显边界或穿地闪烁。低画质连续玩 10 分钟，记录帧率、掉帧与发热。
