2026-10-16；起点 9808ebe，干净 main；目标：电脑网页、手机网页、Windows/macOS/Linux Tauri。用户已确认不新增 Android/iOS 工程。

## 扫描结论

- TypeScript strict / three.js 0.169 / Vite 6；npm run dev:5180、preview:4173；构建先 tsc 再 Vite 和提交页。
- 场景为代码和 GLB，不存在 Unity 场景/预制体。world/{terrain,road,vegetation,scenery,stations,sky,lakeside,vehicle,pose}.ts 构建世界；core/renderer.ts 控制分辨率、雾和低中高档。
- 输入复用 core/keymap.ts，main.ts 控相位，触屏 DOM 摇杆和按钮；小游戏为 canvas。骨骼已有两段 IK 烘焙，但动画倍率封顶与曲柄角不同源；停/快/切车需守住相位。
- Qin 的真实站点是 13（琴音林），此前自由演奏入口却指向 2（南溪茶寮）；模型 2 被纵向拉伸 2.6 倍。
- 路肩/道路/地形/植被已有确定性规则；建筑偏移 18m，交互半径从道路距离推导。应缩小安全偏移、保留广场例外和现有任务序号。
- 天空只随圈数/叙事天数转黄昏，无完整循环。叙事 30 天与视觉小时必须分离，避免 5 分钟循环消耗主线期限。
- 湖边已有照片全景、拖动视角、摇杆行走、钓鱼；沉浸 VR 仅 isSessionSupported 为真时显示入口。补明确状态、拒绝权限回退及重入清理。
- 经营目前仅三商店消费，旅币/库存/章节/位置保存在 gift188.save.v3；增加可选 business 字段，不改存档版本、不清旧档。
- GitHub Actions 负责 Pages 和三桌面 Release，当前 gh 身份 viewerPermission=READ；实现和本地验证不受影响，远端发版需实际写权限。

## 经营完整方案

主角回到十八驿，先完成原来的三十天收集旅程，再决定如何留下人与地方的联系。经营动机是替沿途人留一盏灯：把废置的驿站恢复为骑行旅人的休息点。经营可从第一章尝试，不消耗原剧情天数、不阻断明信片结局；阶段故事逐次从“为自己攒路费”变成“有人愿意再来”。

核心闭环：到建筑采集原料 → 就地加工 → 接受顾客订单 → 等待短服务时间 → 交付赚旅币/口碑 → 升级提高产出和客单价 → 解锁其他建筑与叙事。接受订单时扣产品，完成只领取一次；取消退还产品，无罚款；原料可免费补给，有短冷却避免连点刷取；游戏暂停时经营计时暂停，离线不罚款。全部数值和建筑映射来自 data/business.ts。

| 建筑（实际站号） | 功能 | 资源→产品/服务 | 解锁与叙事 |
|---|---|---|---|
| 起程驿楼 0（十八驿） | 旅人补给台 | 物料→路餐 | 初始开放，第一单启动主角经营故事 |
| 南溪茶寮 2 | 茶馆 | 茶叶→热茶 | 初始开放，茶客来信 |
| 灯影亭 8 | 修灯作坊 | 灯芯→行路灯 | 口碑解锁，夜归者订单 |
| 茶烟小筑 10 | 茶点小院 | 茶叶→茶点 | 口碑解锁，茶农合作 |
| 琴音林 13 | 小型雅集 | 乐谱→听琴席 | 保留小游戏/自由演奏，经营单独入口，听众来信 |
| 竹雨庭 14 | 竹编工坊 | 竹料→竹篮 | 口碑解锁，村民回访 |
| 花房·禽语湖湾 4 | 湖边茶席 | 花草→湖畔茶包 | 口碑解锁，与普通湖边/钓鱼并存 |

每座建筑都有独立库存、已加工产品、订单倒计时、等级和完成数；共享旅币、口碑。每级费用、最多等级、制作数量、服务秒数、客单价、升级口碑要求均配置化。订单顾客为具名来访者，通过订单 UI 和交付后的来信表现，不凭空声称添加了 3D NPC。

章节：第一单“重新开门”；三单/口碑达标“回头客”；跨三座建筑并升级“把灯留着”；完成经营最终目标后收到邀请/阶段收束。已读阶段落盘，订单重复但剧情不重复。经营最终段将原主线 chapter1Done 作为叙事条件，未完成主线时明确提示回十八驿完成明信片；经营收入用于原有商店，因此会使原有限预算更宽松，这是新增玩法有意带来的平衡变化。

时间：视觉 24 小时默认真实 300 秒，现实同步/循环秒数/倍率/偏移/暂停/固定小时可配置。顾客以昼夜改变称呼/需求氛围，但任何时刻都有可完成订单。当前无季节系统，方案使用固定常青季，不加入隐形季节门槛。失败不扣主线资源/心神，升级不会造成软锁，重玩不清除旧功能。

## 平台能力边界

WebXR immersive-vr 依设备、浏览器与安全上下文；普通手机和桌面 WebView 不承诺支持沉浸 VR。所有平台保留触摸/鼠标全景、方向控制和钓鱼；失败提示后留在普通湖边。横屏锁定仅在受支持的用户手势/全屏环境尝试；iOS 等拒绝时显示旋转提示并允许继续竖屏。

参考：[WebXR](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API)、[权限](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API/Permissions_and_security)、[横屏锁定](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。
